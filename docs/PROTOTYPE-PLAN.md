# ScribeTrace: spikes before Stage 1 coding

About one week, one person plus CI. Throwaway code; only findings and fixtures are kept. Rules under test: [ADR 0006](adr/0006-staged-mvp-and-delivery-shape.md), [0007](adr/0007-per-device-history-log-merge-and-forget.md), [0009](adr/0009-zotero-integration.md). Numbers from the [QA review](reviews/qa-architecture-v2.md), adapted to the simplified log rules.

**Gates:** no Stage 1 production code until SPIKE-1, 2, 3 and 4 all pass. A failed gate goes to the user (SPIKE-3 fail = Decision for the user #4; SPIKE-4 fail = reopen the shell choice).

| Spike | Hypothesis | Test | Pass | Fail | Time |
|---|---|---|---|---|---|
| **3 Zotero live** (day 1) | Zotero 7's local interface gives enough to import marks | Real Zotero 7, dummy library, interface enabled; record answers as fixtures; stand-in server replays them in CI (> 100 items, empty, trashed, malformed, 404, 500, oversize, slow) | Metadata, child annotations, text, colour, page and boxes, dates all present; 100 items < 200 ms; all CI cases behave as ADR 0009 (5 s, 15 MB) | Any data kind missing or paging unusable: stop, ask the user | 2 days |
| **1 Log merge + device check** | Union of per-device files gives one state in any order; the collision check never clobbers or loops | `proptest`: 5 devices, random order, duplicate and split deliveries. Table tests: cloned id, restored backup, crash before the record, missing `device.json`. Reads leave files byte-identical. 10,000-event replay | `merge(A,B)=merge(B,A)` and merge twice = once in 10,000 of 10,000 runs; each collision case ends in a new id and no changed file; replay < 500 ms | Any order dependence, rewritten byte or id loop | 2 days |
| **2 Purge** | `covers` hides exactly what the purger saw, independent of clocks | Pure function `visible(events, purges)`: wrong clocks both ways; unseen offline event (visible, hidden by a second purge); two purges in any order; new history after a purge | 100% of covered events hidden whatever `ts` says; 0 leaks into timeline, export, counts; same result for 10,000 random orders | Any leak or order dependence | 1 day |
| **4 Shell + PDF.js** | Tauri's system web views render and select text in a large PDF within budget | Minimal Tauri v2 window with PDF.js, 50 MB / 500-page PDF, CI on Ubuntu (WebKitGTK), Windows (WebView2), macOS (WKWebView); installer size, cold start and idle memory recorded | First page < 1.5 s (ceiling 2.0 s); selection equals fixture text; box returned < 50 ms; cold start < 2 s; idle memory < 120 MB; numbers fill the [lightness budget](ARCHITECTURE.md#lightness-budget) | Blank page, crash, text offset or a missed ceiling on any system | 3 days (parallel) |

**After the gate.** S2-A (before Stage 2): marks survive re-open and text-layer differences between PDF.js and Zotero; pass = 95% of 200 marks re-attached on a 10-PDF corpus, the rest orphaned, none wrongly attached; 3 days ([ADR 0011](adr/0011-reader-pdf-markdown-and-anchoring.md)). Product gate at the end of Stage 1: do users value the history viewer?
