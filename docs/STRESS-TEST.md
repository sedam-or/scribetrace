## 4. Lean Architecture Check (v3.0)

**Verdict:** **ACCEPTED.** The v3.0 architecture simplifications significantly improve testability while preserving system safety across all stress-test scenarios:
1. **HLC & 24 h bound removal:** Still testable & safe. Eliminates the false clock-skew quarantine risk (ST-22); `ts` is purely cosmetic, and union merge ordering is clock-agnostic.
2. **Simplified `device.json` (`last_id` check):** Still testable & safe. Prevents sync storms and UUID clobbering (ST-04) via a single deterministic file-tail check in SPIKE-1.
3. **`corrupt/` file removal (in-memory skip):** Still testable & safe. Eliminates sync conflicts on diagnostic logs (ST-09); invalid lines are skipped and surfaced in UI/`check`.
4. **Passive peer purge banner (no stored state):** Still testable & safe. Eliminates persistent modal state machines; purge filtering is a pure function over `covers`.
5. **Note conflict last-writer-wins:** Still testable & safe. Avoids interactive conflict resolution complexity; all revisions remain in append-only log.
6. **Update manifest removal (browser release link):** Still testable & safe. Completely eliminates update check MitM / payload tampering (ST-17) and drops in-app networking.
7. **Export hash tracking & CLI merge deferral:** Still testable & safe. Replaced by simple file markers; lowers Stage 1 scope without impacting format safety (ST-20).
* **PROTOTYPE-PLAN.md Verification:** All pass/fail metrics remain quantified (SPIKE-1: 10k/10k proptest runs, < 500 ms replay; SPIKE-2: 100% suppression of in-covers events; SPIKE-3: 5 fields, < 200 ms; SPIKE-4: 3-OS render < 1.5 s, memory < 120 MB RSS). SPIKE-1/2 accurately reflect the new purge and device check semantics. Zero gaps identified.
