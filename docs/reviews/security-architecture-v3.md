## 1. Simplification Log Delta Evaluation

The Simplification log (§8 of `docs/ARCHITECTURE.md`) discards complex mechanisms introduced in earlier drafts. Below is the security and privacy assessment for each removal:

| Removal / Change | Security Property Impact | Verdict | Analysis & Rationale |
| :--- | :--- | :---: | :--- |
| **1. HLC & 24 h future bound removed** (`ts` display-only) | Clock skew / reordering tamper resistance | **SAFE** | State reconstruction relies on per-device monotonic sequences (`seq`) and deterministic set union by item `id`. Timestamps are purely cosmetic; manipulating system clocks cannot corrupt state, omit events, or alter history transitions. |
| **2. `corrupt/` files removed** (skip & count in-memory) | Denial of Service & Disk Flooding | **SAFE** *(Hardening)* | Eliminates disk-filling amplification attacks where crafted invalid lines spam the host drive. In-memory skip with UI/CLI error counting retains full diagnostic visibility without filesystem risk. |
| **3. Peer purge prompt $\rightarrow$ passive banner** | Sync state race conditions & UX spoofing | **SAFE** | Eliminates complicated `purge_answers` state machines in `device.json`. A non-modal banner with an explicit "Delete hidden files" button avoids sync races while preserving user consent. |
| **4. Purge hides ONLY events within `covers`** | History erasure / confidential paper privacy | **WEAKENING** *(Trade-off)* | **Real Privacy Regression:** Unseen offline events generated on another device (`seq > covers[device]`) survive a purge and become visible once synced. For strictly confidential manuscripts (e.g., double-blind reviews), "Forget" is not an instantaneous global erasure. *(See §3 for mitigations)*. |
| **5. Update manifest removed** (opens browser release URL) | Remote updater exploit / RCE / MitM | **SAFE** *(Major Hardening)* | Eliminates all in-app HTTP clients, TLS verification, JSON manifest parsing, and binary execution logic. Zero remote attack surface in the application binary; update visibility is safely delegated to the OS browser. |
| **6. Export hash tracking $\rightarrow$ marker line** | File corruption & external sync loops | **SAFE** | A standardized marker line (`# Generated by Palimpsest`) replaces complex hash caches. Palimpsest strictly overwrites files it owns and refuses to touch user-modified files, avoiding external vault sync loops. |

## 2. Link Design Evaluation (ADR 0013)

**Verdict:** **APPROVED (No new attack surface)**
* **Zero New Components:** Delegating web link capture to the official Zotero Connector avoids shipping a custom browser extension, native messaging host, or web scraping engine.
* **Preserves SEC-1 Network Invariant:** Palimpsest opens zero outbound internet sockets. Links and metadata traverse the existing local loopback broker (`127.0.0.1:23119`, SEC-33) on explicit user action.
* **Boundary Validation:** Web links are treated as untrusted strings (SEC-8) and dispatched strictly through system browser handler allowlists (`http`, `https`, `zotero`; SEC-23, SEC-24).

## 3. Privacy Trade-Off: Forget / Purge Semantics for Confidential Papers

Under lean sequence-bounded purge (`covers = {device: highest seq seen}`):
* **The Risk:** If Device B creates annotations while offline and Device A executes "Forget Paper History", Device A's purge event cannot cover sequence numbers it has never seen. When Device B eventually syncs, its unseen annotations reappear on all devices until a new forget action is performed.
* **Assessment:** While mathematically robust and conflict-free, users handling double-blind reviews or NDA manuscripts may assume "Forget" provides an irrevocable, global guarantee.
* **Actionable Recommendation:**
  1. The "Forget Paper History" confirmation dialog MUST explicitly disclose: *"Purge covers all history synced to this machine up to now. If other devices have offline annotations, bring them online and repeat Forget to remove remaining history."*
  2. Document in user help that for zero-trace disposal of confidential papers, deleting the paper folder or workspace directly is required.
