# Round 2: QA Critique & Validation Bar

**Reviewer:** Senior QA Engineer (agent-1793867530011-poqhdm)  
**Document Under Review:** `docs/debate/01-proposal.md`  
**Lens:** Validation, Testability, and the Launch Quality Bar  

---

## 1. Where I Agree

1. **Radical Scope Reduction (PDF + Markdown):** Dropping EPUB and HTML/arXiv for the MVP eliminates ~70% of format-specific rendering quirks, reflow heuristics, CSS column fragmentation, and iframe DOM security traps. Validating PDF.js and plain Markdown is bounded and achievable.
2. **Zero Write-Back to Zotero:** Rejecting direct writes into `zotero.sqlite` is a critical quality safeguard. A third-party app corrupting a PhD student's 5,000-paper reference library is a catastrophic, unrecoverable defect. Read-only ingestion is safe and deterministically testable.
3. **Open CLI Validator (Bet 10):** Keeping a standalone command-line tool to inspect and validate sidecar files provides an automated, headless test oracle that bypasses desktop UI flakiness.

---

## 2. Strongest Objection: The "Understanding Diff" & Sync Mirage

PM's proposal bets heavily on **Bet 1+2 (Time Machine & Understanding Diff)** and **Bet 6 (Obsidian Mirror)**. From a verification and reliability perspective, both carry severe launch risks:

1. **The "Understanding Diff" (Feature 2) is untestable without semantic intent:**  
   Comparing marks between "March vs now" sounds compelling in prose, but what does the diff engine actually assert? If a researcher resized a highlight box, fixed a typo in a comment, or dragged an arrow 10 pixels to the left, is that an "evolution of understanding" or UI jitter? Rendering two asynchronous PDF canvas states side-by-side with synchronized zoom, pan, and visual diffing is notoriously flaky and prone to rendering artifacts across OS display scaling (100% vs 150% fractional scaling). If history is an unproven user need (PM §4), shipping a buggy, sluggish visual diff will kill user trust on day one.
2. **The Obsidian Mirror (Feature 6) is a dual-master conflict trap:**  
   A live bidirectional mirror between Palimpsest and an active Obsidian vault invites race conditions. If Obsidian (or Obsidian Sync / iCloud) touches `paper.md` while Palimpsest's file watcher is processing a note auto-save, we face write collisions, file-locking contention on Windows, and split-brain states. Validating distributed file synchronization without a server is notoriously non-deterministic.

---

## 3. What I Would Cut

1. **Cut Feature 2 ("Understanding Diff") from the MVP:**  
   Replace continuous visual diffing with **discrete named versions in a history list** (Feature 1). Users can inspect and restore past states sequentially. Defer side-by-side visual diffing until users prove they care about history.
2. **Downgrade Feature 6 ("Obsidian Mirror") to One-Way Vault Export:**  
   Do not implement bidirectional filesystem synchronization in v0.1. Palimpsest should write/project notes and quotes into a designated vault folder as read-only exports, or append on user action. Do not watch or parse arbitrary external edits from Obsidian until the core event log is stable.

---

## 4. Alternative I Would Defend: Discrete Milestone Snapshots

Instead of an arbitrary time-scrubber slider (which invites continuous state interpolation bugs and event replay lag), I defend **Discrete Milestone Snapshots**:
- Readers do not think in continuous milliseconds; they think in intellectual milestones: *"First skim"*, *"Seminar discussion"*, *"Thesis chapter draft"*, *"Reviewer rebuttal"*.
- **Why it wins for QA:** A snapshot is a frozen, immutable event watermark $W$. Testing is 100% deterministic: `render(snapshot_id) == frozen_state`. We can fuzz snapshot creation, assert immutability, and guarantee zero visual regression across reboots.

---

## 5. Validation & Launch Quality Bar (How We Know It Works)

We cannot launch on optimistic qualitative feedback alone. The MVP must meet five measurable, automated gates:

```
+---------------------------------------------------------------------------------------------------------+
|                                    PALIMPSEST MVP LAUNCH QUALITY GATES                                  |
+--------------------------+-----------------------+------------------------------------------------------+
| Quality Dimension        | Target Metric / SLA   | Verification Mechanism & Tooling                     |
+--------------------------+-----------------------+------------------------------------------------------+
| 1. Document Integrity    | 0 bytes modified      | Cryptographic assertion: SHA-256 before == after     |
|                          | (Absolute Zero)       | across 100 diverse PDFs (scanned, vector, encrypted).|
+--------------------------+-----------------------+------------------------------------------------------+
| 2. Crash Durability      | ≤ 1.0 s data loss     | Chaos test: Automated typing + asynchronous SIGKILL; |
|                          | (Zero Corruption)     | assert log recovers cleanly with 0 malformed lines.  |
+--------------------------+-----------------------+------------------------------------------------------+
| 3. Zotero Ingestion      | 100% Import Accuracy  | Ingest 50 real-world Zotero libraries; assert all    |
|                          | (< 3.0 s import)      | existing native highlights translate to v1 events.   |
+--------------------------+-----------------------+------------------------------------------------------+
| 4. Rendering Speed       | < 1.5 s Page 1        | Benchmark on 4-core / 8 GB hardware with 50 MB /     |
|                          | (Cold Cache)          | 500-page PDF; annotation latency < 50 ms.            |
+--------------------------+-----------------------+------------------------------------------------------+
| 5. Usability Validation  | < 3 min First Value   | 5 target researchers complete: (1) open from Zotero, |
|                          | (Unassisted)          | (2) highlight, (3) copy quote, (4) restore a mark.   |
+--------------------------+-----------------------+------------------------------------------------------+
```

If Gate 1 (Integrity) or Gate 2 (Durability) fails even once, **we do not launch**. An annotation tool that corrupts data or loses thoughts cannot survive in academia.
